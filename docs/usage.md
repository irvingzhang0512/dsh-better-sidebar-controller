# 使用指南：通过 Agent 控制侧边栏

本指南说明如何配置 `dsh-better-sidebar-controller`，以及如何让 Agent 操作 better-sidebar 和 DSH 官方右侧栏。适用于插件 `0.3.0`，目标组合为 DSH desktop `0.2.0-rc.2`、better-sidebar `0.25.0`；实际验证范围见 [验证记录](VERIFICATION-0.3.0.md)。

首次使用按顺序阅读：[插件与侧栏的关系](#插件与侧栏的关系) → [配置](#配置) → [操作分类与示例](#操作分类与示例) → [完整使用流程](#完整使用流程)。遇到问题查看 [结果与排错](#结果与排错)。

## 插件与侧栏的关系

你向 Agent 发出自然语言指令，Agent 读取 `sidebar-controller` 技能，再调用本插件的工具，由当前会话界面执行操作。

| 组成 | 负责什么 |
|---|---|
| DSH 官方右侧栏 | 原生文件等标签的展示，以及右侧栏的显示／隐藏 |
| better-sidebar | 文件打开、文件夹窗口、工作区文件树、底部工作台，以及侧边卡片设置 |
| 本增强扩展 | 为 Agent 提供打开、查询、切换、返回、关闭文件与文件树操作工具，并同步文件状态 |

本扩展依赖已启用且兼容的 better-sidebar。配置也保存于 better-sidebar 的设置中，无需创建独立配置文件。文件的显示位置沿用 better-sidebar 设置，可能位于官方右侧栏或底部工作台；`show_sidebar`／`hide_sidebar` 只控制官方右侧栏。

文件夹窗口、网页和终端不计入当前／上一文件。本扩展不提供网页或文件夹窗口的关闭、返回工具，也不负责文件内容编辑。

## 配置

### 1. 确认前置条件

使用 DSH desktop，并确认以下两个插件均已安装、启用：

- `dsh-better-sidebar@0.25.0`。
- `dsh-better-sidebar-controller@0.3.0`。

进入「设置 → 侧边卡片」，应能找到「Sidebar Controller 增强控制」卡片。缺少卡片时先核对插件加载和依赖状态；下面的工具开关不能替代安装或启用插件。

### 2. 按用途开启能力

1. 打开「设置 → 侧边卡片」。
2. 如果需要 Agent 打开文件、文件夹或网页，在「常规」开启 **为模型注入侧边栏打开工具**。
3. 如果需要 Agent 查询状态、管理文件标签、操作文件树或控制右侧栏，在「Sidebar Controller 增强控制」卡片点击 **功能设置**，开启 **允许模型管理侧边栏**。
4. 如果需要“回到刚才那个文件”，两个开关都要开启。
5. 按需调整管理开关下的 **列出隐藏项** 和 **单层条目上限**。

增强卡片会显示打开能力的关联状态及其设置位置。打开开关只有上游「常规」里的一个，不需要再开启第二个打开开关。

### 3. 配置项一览

| 配置项 | 所在位置 | 有效默认值 | 影响范围 |
|---|---|---|---|
| 为模型注入侧边栏打开工具 | 侧边卡片 → 常规 | 未设置时关闭；保留已有值 | 上游 `sidebar_open`，增强 `better_sidebar_open`，兼容 `open_file` |
| 允许模型管理侧边栏 | 增强控制卡片 → 功能设置 | 关闭 | 状态查询、文件关闭／切换、目录操作、右侧栏显隐；与打开开关共同允许返回上一文件 |
| 列出隐藏项 | 增强控制卡片 → 功能设置 | 开启 | 目录列举与刷新结果是否包含点开头的隐藏条目 |
| 单层条目上限 | 增强控制卡片 → 功能设置 | 1000，最小 1 | 目录单层返回条目数；超出时结果标记 `truncated` |

管理关闭时，隐藏项和条目上限设置不显示，原有值保留。这两项不改变文件打开权限，也不会让目录工具访问工作区外的目录。

设置自动保存，并随开关变化动态注册或移除工具；执行和队列重放前也会重新核对权限。关闭某类能力会清理该类尚未执行的指令，保留已经打开的标签。两个开关均关闭时，讨论工作台使用的内部文件状态同步服务仍可运行。

维护者需要核对存储时：打开能力使用上游 `agentOpenTools`；本扩展的 `agentControlTools`、`includeHiddenEntries`、`maxListedEntries` 保存在上游 `pluginSettings` 的控制器条目中。宿主读取实际加载的 better-sidebar 持久设置；日常使用直接在界面修改，无需手工填写设置命名空间。

### 4. 两个开关怎样组合

下表统计本扩展的工具，不包含上游独立注册的 `sidebar_open`。

| 打开开关 | 管理开关 | 本扩展可用能力 | 工具数量 |
|---|---|---|---|
| 关闭 | 关闭 | 无模型工具 | 0 |
| 开启 | 关闭 | 打开文件、文件夹窗口、网页，以及兼容打开 | 2 |
| 关闭 | 开启 | 查询、切换和关闭已打开文件，操作文件树，显示／隐藏右侧栏 | 9 |
| 开启 | 开启 | 上述全部能力，加上返回上一文件 | 12 |

只开启管理时，可以操作已打开的文件；`reopen_previous_file` 仍不可用，因为它同时需要打开权限。

### 5. 检查配置是否生效

在需要操作的会话中对 Agent 说：

> 请使用 sidebar-controller 技能，检查当前可用的侧边栏工具。告诉我 better_sidebar_open、get_sidebar_state 和 reopen_previous_file 是否可用，以及对应哪些开关。

技能随插件自动注册，无需手动复制。技能能被读取不代表工具已经授权：Agent 必须检查实际可用工具列表，不能只凭文档中的名称假定工具存在。

设置变化后等待同步，再发起新一轮对话核对。如果当前会话仍没有更新工具列表，可在新会话检查。若两个开关都已开启但工具仍不可用，检查依赖、插件加载及设置读取状态。

## 操作分类与示例

你只需要说自然语言。下面的调用示例用于理解 Agent 应选择哪个工具；无需自己提供会话编号。参数和返回字段的完整定义见 [工具参考](tools.md)。

### 一、打开内容

需要开启 **打开开关**。技能优先选择 `better_sidebar_open`，自动识别文件、文件夹和 HTTP(S) 网页。

| 对 Agent 说 | 应调用的工具 |
|---|---|
| “用侧边栏控制技能打开 docs/会议纪要.md” | `better_sidebar_open(target: "docs/会议纪要.md")` |
| “在侧边栏打开 F:/资料/项目计划.md” | `better_sidebar_open(target: "F:/资料/项目计划.md")` |
| “把 docs 文件夹作为一个窗口打开” | `better_sidebar_open(target: "docs")` |
| “在侧边栏打开 https://example.com” | `better_sidebar_open(target: "https://example.com")` |
| “用兼容工具打开工作区里的 docs/会议纪要.md” | `open_file(path: "docs/会议纪要.md")` |

相对路径按调用会话的工作目录解析。文件系统目标必须存在且可访问；增强入口允许工作区外的绝对路径。旧 `open_file` 保留工作区限制，通常只用于旧调用兼容。上游 `sidebar_open` 与增强工具同时存在时，技能优先使用增强入口。

`title` 是可选的建议标题，例如 `better_sidebar_open(target: "docs/会议纪要.md", title: "本周会议")`。实际显示沿用上游接口支持的行为。

**打开文件夹窗口**会创建以该文件夹为根的浏览窗口；**展开目录**则操作现有工作区文件树。打开外部文件夹不会改变会话工作目录，也不会扩大目录工具的访问范围。

网页通过 DSH 原生浏览器打开，只接受 HTTP(S)；本地目标使用普通路径，不使用 `file:` URL。成功表示客户端接受了打开操作，网站是否可读仍取决于网络、登录及网页嵌入限制。

### 二、管理文件标签

需要开启 **管理开关**；返回上一文件还需要 **打开开关**。

| 对 Agent 说 | 应调用的工具 |
|---|---|
| “现在打开的是哪个文件？还有哪些文件开着？” | `get_sidebar_state()` |
| “切到已经打开的 docs/项目计划.md” | `activate_file(path: "docs/项目计划.md")` |
| “回到刚才那个文件” | `reopen_previous_file()` |
| “关闭当前文件” | `close_file()` |
| “把 docs/会议纪要.md 关掉” | `close_file(path: "docs/会议纪要.md")` |

查询结果中的 `currentFile` 是当前文件，`previousFile` 是上一文件，`openedFiles` 是已打开文件列表。官方右侧栏与底部工作台中的文件统一纳入状态；鼠标打开、切换或关闭文件也会同步。焦点落在非文件页面时，当前文件可能为空。

切换工具用于已经打开的文件，不能用它打开一个新文件。已知的工作区外文件也支持关闭、切换和返回；返回工具使用系统记录的上一文件，不要求 Agent 自己记住路径。

关闭文件后，界面可能自动激活另一文件，应再次查询状态确认。上述操作不用于网页、目录窗口或终端。

### 三、操作工作区文件树

需要开启 **管理开关**。这些工具使用现有 better-sidebar 文件树，并限制在调用会话的工作区内。

| 对 Agent 说 | 应调用的工具 |
|---|---|
| “列一下工作区根目录” | `list_files()` |
| “列一下 docs 里的文件” | `list_files(path: "docs")` |
| “在文件树里展开 docs” | `expand_folder(path: "docs")` |
| “收起文件树里的 docs” | `collapse_folder(path: "docs")` |
| “我刚在外部新建了文件，刷新文件树” | `refresh_tree()` |

路径不确定时先列目录，再用返回的真实路径打开文件。结果是否包含隐藏条目，以及单层返回多少条目，由前述列举设置控制。达到上限时留意 `truncated`，不要把截断结果当作完整目录。

### 四、控制官方右侧栏显示

需要开启 **管理开关**。

| 对 Agent 说 | 应调用的工具 |
|---|---|
| “显示官方右侧栏” | `show_sidebar()` |
| “隐藏官方右侧栏” | `hide_sidebar()` |

这两个工具控制 DSH 官方右侧栏的展开状态，不独立控制 better-sidebar 底部工作台，也不操作左侧会话导航。隐藏侧栏不会关闭其中的文件。

## 完整使用流程

先开启两个开关。在当前工作区选择两个已有且可读的文件；以下以 `docs/会议纪要.md` 和 `docs/项目计划.md` 为例，没有这些文件时使用实际列举到的文件。

| 步骤 | 对 Agent 说 | 工具与预期 |
|---|---|---|
| 1. 列目录 | “使用 sidebar-controller，列一下 docs，确认两个文件的路径” | `list_files(path: "docs")`，取得真实路径 |
| 2. 打开文件 | “打开会议纪要，然后打开项目计划” | 依次调用 `better_sidebar_open`，等待各自执行确认 |
| 3. 查询状态 | “现在打开的是哪个文件？上一文件是什么？” | `get_sidebar_state()`；当前为项目计划，上一文件为会议纪要 |
| 4. 切换 | “切到已经打开的会议纪要” | `activate_file(path: "docs/会议纪要.md")`；当前为会议纪要 |
| 5. 返回 | “回到刚才那个文件” | `reopen_previous_file()`；返回项目计划 |
| 6. 关闭并确认 | “关闭当前文件，再告诉我还有哪些文件开着” | `close_file()` 后查询状态；项目计划从已打开列表移除 |

如果中间出现排队或确认超时，先按下一节处理，再继续流程。你也可以用鼠标进行切换，再让 Agent 查询，核对两种操作得到的状态是否一致。

操作只投递到调用会话。需要操作另一个会话时，在那个会话发出指令；切换前台界面不会让当前调用自动改为操作其他会话。

## 结果与排错

### 技能或工具不可用

| 现象／结果 | 处理方法 |
|---|---|
| 找不到 `sidebar-controller` 技能或增强设置卡 | 检查增强插件及 better-sidebar 是否安装、启用和成功加载 |
| 技能可见，但缺少某个工具 | 按开关组合表检查授权，再核对当前会话实际可用工具列表 |
| `TOOL_DISABLED` | 对应能力已关闭；开启后再发新指令，该类尚未执行的旧指令已清理 |
| `SIDEBAR_UNAVAILABLE` | 按返回的 `message` 检查依赖、兼容版本或目标界面能力；此结果不表示已经排队 |
| `SETTINGS_UNAVAILABLE` | 无法读取权威设置，需要恢复设置读取；不会用客户端缓存或默认开启继续执行 |

better-sidebar 缺失、停用或不兼容时，本扩展不注册模型工具，也不接受排队。技能不能绕过能力开关。

### 等待执行或确认

| 结果 | 含义与下一步 |
|---|---|
| `OK` | 客户端已确认接受操作；网页标签打开不保证网页加载成功 |
| `QUEUED` | 依赖和权限有效，但调用会话界面暂未接入；等待该会话界面连接，不重复发送同一操作 |
| `QUEUE_FULL` | 当前会话已有 64 条等待指令，新指令未入队；等待队列处理后再决定是否发起 |
| `BRIDGE_TIMEOUT` | 4 秒内未收到确认，结果未知，操作可能已经发生；先查询状态或查看界面，避免重复打开 |

管理开启时，确认超时后先调用 `get_sidebar_state`。管理关闭时先查看界面，或开启管理后查询。已发送但未确认的操作不会在重连后自动重复；仅尚未发送的队列会重放。

### 路径或文件状态不符合条件

| 结果 | 处理方法 |
|---|---|
| `FILE_NOT_FOUND` 或路径不可读 | 核对路径及访问权限；工作区内可先列目录，不反复猜文件名 |
| `PATH_OUTSIDE_WORKSPACE` | 兼容打开或目录工具越界；打开外部内容使用增强入口，目录工具仍限工作区 |
| `INVALID_TARGET` | 检查目标格式；网页只接受 HTTP(S)，本地文件使用普通路径 |
| `FILE_NOT_OPEN` | 目标尚未打开；需要打开时调用增强打开工具 |
| `NO_CURRENT_FILE` | 当前没有可操作的文件；先查询已打开文件或查看焦点位置 |
| `NO_PREVIOUS_FILE` | 没有记录到上一文件；先打开或切换文件再使用返回 |
