# 设计与技术契约（待确认）

## Context

来源为本库冻结的 `docs/DESKTOP-WORKFLOWS-20261014.md`、F014 和架构中的对应草案。当前基础 API 的 getState／subscribe 返回 currentFile、fileCandidate、source、workspaceRoot、connected；它们是观察镜像，不是编辑绑定接口。文档插件拥有结构化绑定，工作台持有其 host lease。

## Goals / Non-Goals

目标是使浏览文件、参考材料和固定编辑对象可靠分离，并证明多连接状态与现行门禁共同成立。不增加新开关、不复制 Better Sidebar 文件树、不新增文档节点工具、不实现录音或图片识别。

## Decisions

- 工作台显式 bind／unbind、pinned=null 和 lease 生命周期在工作台领域定义；控制器不得以当前文件更新替代显式绑定。浏览转写、图片、项目 JSON、表格、报告、URL 或目录均不得迁移固定目标。
- 增强打开可处理外部路径；材料／输出／目标的真实 cwd 检查仍由工作台和文档工具执行，候选不能携带授权。
- 多窗口观察需有连接来源与有效性；同会话其余在线连接保持有效；最近打开与当前在线观察区分。具体合并算法须在确认版补齐，不能静默选择不同规则。
- 现行权限两开关、权威配置读取、有效依赖和 0／2／9／12 工具矩阵保持。队列上限 64、4 秒确认超时和现行错误语义保持，未经确认不调整。
- 单独记录保存／已投递／客户端完成，断线超时不重放副作用。只销毁自有 anchor、timer、subscriber，不关闭用户应用、标签或改布局。

## Risks / Trade-offs

原目标是 DSH 0.2.0-rc.2 + Better Sidebar 0.25.0；现已交付 DSH 0.2.1-rc.2 + Better Sidebar 0.28.0 的兼容与套件组合。该事实不是原工作流完整交付，应在实施前确认新的固定验收目标。仅单客户端回归不足以证明多窗口一致性。

## Migration Plan

本次只迁移文档，无数据、配置和代码迁移。后续实施应保留当前开关与用户配置；无需恢复旧 settings 客户端镜像。先隔离环境联合验证，再依据既有日常交付授权正常退出、冷备份和安装固定版本。未确认前不执行。
