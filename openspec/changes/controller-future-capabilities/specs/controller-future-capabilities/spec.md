# 早期未来能力与范围边界

## Purpose

本能力保存 F008 和原始 requirements.txt 第 4.2、8、12、13、14、21 节中未进入现行产品的设想。以下为待确认方案的边界要求和接受条件，文件管理策略、语音归属及文档节点接口尚未批准，不表示功能已可用。

## ADDED Requirements

### Requirement: F008 结构节点职责分离

未来 Current File → Current Node 协作 SHALL 继续由控制器负责文件选择，文档插件负责段落、表格、单元格等结构节点；不得把未来设想登记成已存在的控制器节点工具。

#### Scenario: 评估节点协作

- **WHEN** 准备新增当前节点能力
- **THEN** 先确认文档服务、绑定和选区语义以及验收场景，再实施；现有文件选择不声称可以定位任意文档节点。

### Requirement: 原需求 4.2 与 8 文件管理扩展

未来文件查找／创建及文件删除、移动、复制、重命名、目录创建／删除 SHALL 保留为独立待确认范围；实施前 MUST 明确真实路径围栏、冲突、失败恢复及破坏性操作确认策略。

#### Scenario: 请求扩展文件维护

- **WHEN** 用户提出现有打开／关闭以外的文件维护
- **THEN** 先完善具体操作与验收，不把现有打开能力作为删除或覆盖的授权。

### Requirement: 原需求 14 模糊文件选择

未来独立查找能力 SHALL 在名称不唯一时返回可辨认候选并请求选择，不随机打开；未找到和无法读取必须区分。原始 success/error 示意不取代现行结构化结果契约。

#### Scenario: 存在多个同名候选

- **WHEN** 未来查找返回多个匹配
- **THEN** 展示候选位置并等待明确选择；不得挑第一项或伪造不存在结果。

### Requirement: F008 与原需求 12至13 语音范围

语音输入经 STT 成为文本后 SHALL 可沿用文件工具流程；控制器自身不承担独立录音／识别引擎。未来显式操作模式或“操作”前缀须另行确认，当前不要求用户切换工作模式。

#### Scenario: 讨论语音口令

- **WHEN** 考虑区分口述正文和文件命令
- **THEN** 先明确由哪一层分类与确认，保留当前普通文本工具入口，不自动把口述文字当作执行命令。
