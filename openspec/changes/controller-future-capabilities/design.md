# 设计状态

## Context

来源为原始 requirements.txt 与 SPEC F008。原始文档既含已经落地的文件控制，也含“未来”标记；本变更仅接收后者。原需求示意错误结果使用 success/error，现行实际工具使用 ok/code/message，不反向改运行协议。

## Goals / Non-Goals

确保未实施愿望不丢失，并保留跨插件职责。当前不确定新增工具名称、存储结构、具体默认值、删除确认机制或语音协议，不实施文件维护、节点控制或 STT。

## Decisions

文件与目录维护须先明确 cwd/realpath、重名、覆盖、回滚和授权。节点选择依赖文档插件的结构能力；语音识别属于语音侧，控制器只复用文本命令入口。无上游公开扩展点时先提出最小接缝，不私改上游代码。

## Risks / Trade-offs

早期原始范围并非用户批准的完整产品计划；不能仅靠通过文档校验升级为承诺。模糊路径必须返回候选，不借未来搜索能力放宽现有打开围栏。

## Migration Plan

仅保留文档，不修改原需求或配置，无运行迁移。

## Open Questions

是否需要各操作、破坏性确认及恢复策略；节点接口归属；语音模式是否需要、何种前缀与确认。应逐项确认、可拆成更小 change 后实施。
