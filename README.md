# dsh-better-sidebar-controller

**通过 Agent 操作 better-sidebar 和 DSH 官方右侧栏。**

这是 better-sidebar 的模型控制增强扩展：你用自然语言告诉 Agent 要打开什么、切到哪个文件或展开哪个目录，Agent 通过插件提供的工具操作现有界面。插件依赖 better-sidebar，功能和配置都融入「设置 → 侧边卡片」，源码保持独立。

当前版本 `0.3.0`，目标组合为 DSH desktop `0.2.0-rc.2`、better-sidebar `0.25.0`。验证范围见 [验证记录](docs/VERIFICATION-0.3.0.md)。

## 可以做什么

| 操作类别 | 支持的操作 | 对 Agent 说 |
|---|---|---|
| 打开内容 | 打开文件、文件夹窗口、HTTP(S) 网页；文件可使用工作区外的绝对路径 | “在侧边栏打开 F:/资料/项目计划.md” |
| 管理文件标签 | 查询当前／上一文件和已打开文件，切换、返回、关闭文件 | “切到已经打开的会议纪要”“回到刚才那个文件” |
| 操作文件树 | 列举工作区目录，展开、折叠、刷新 better-sidebar 文件树 | “在文件树里展开 docs” |
| 控制侧栏显示 | 显示、隐藏 DSH 官方右侧栏 | “显示右侧栏” |

better-sidebar 提供文件打开、文件树和底部工作台。文件具体显示在官方右侧栏还是底部工作台，沿用 better-sidebar 的设置；两处的文件状态统一记录，鼠标操作也会同步。显示／隐藏工具只控制官方右侧栏。

网页和文件夹窗口可以打开，但不计入当前／上一文件，也没有对应的关闭或历史导航工具。这组工具负责界面操作；编辑文件内容需要 Agent 使用其他工具。

## 怎么配置

所有配置都从 **设置 → 侧边卡片** 进入。先确认 better-sidebar 和本扩展已安装、启用。

| 想启用的能力 | 设置入口 | 开关 |
|---|---|---|
| 让 Agent 打开内容 | 「常规」 | 为模型注入侧边栏打开工具 |
| 让 Agent 查询、切换、关闭文件以及操作文件树和侧栏显示 | 「Sidebar Controller 增强控制」→「功能设置」 | 允许模型管理侧边栏 |
| 让 Agent 返回上一文件 | 上述两个入口 | 两个开关都开启 |

两个开关未设置时均关闭；已有上游打开开关的值保留。想使用全部操作，就开启两个开关。增强卡片显示打开能力的关联状态，打开开关仍在「常规」，不重复设置。

管理设置下还可调整「列出隐藏项」（默认开启）和「单层条目上限」（默认 1000）。关闭管理后这两项隐藏，已保存的值保留。设置自动保存，工具随开关变化自动更新；关闭能力不会关闭已打开的标签。

完整的配置步骤、四种开关组合和生效检查见 [使用指南：配置](docs/usage.md#配置)。

## 怎么让 Agent 使用

插件捆绑 `sidebar-controller` 技能，由 DSH 自动注册。你可以先说：

> 请使用 sidebar-controller 技能，检查当前可用的侧边栏工具，告诉我打开和管理能力是否已开启。

确认后直接发出指令，例如：

- “用侧边栏控制技能打开 docs/会议纪要.md。”
- “把 docs 文件夹作为一个窗口打开。”
- “在侧边栏打开 https://example.com。”
- “现在打开的是哪个文件？还有哪些文件开着？”
- “关闭当前文件。”

技能优先使用增强入口 `better_sidebar_open`。技能可见不代表全部工具已启用；工具仍受两个开关控制。你无需手写调用代码或提供会话编号。

打开相对路径时，以调用会话的工作目录为基准。目录工具和旧 `open_file` 限制在工作区内；增强打开允许外部绝对路径。操作只投递到调用会话。

`QUEUED` 表示等待界面连接后执行；确认超时表示结果未知，应先查询状态或查看界面，再决定是否重试。打开网页标签也不保证网站加载成功。
